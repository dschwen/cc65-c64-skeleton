Script / Conversation Editor

One top-level script, conversation, or room declaration per file - the Makefile compiles assets/scripts/<ID>.script straight to this resource ID on build (tools/compile_script.py --single-output). Nothing here is compiled live; save the source, then build the cartridge to see compiler errors.

DSL syntax reference

A file holds exactly one script (a linear cutscene), conversation (keyword-matched topics), or room (numbered entries) declaration. All three share the same statement language inside their bodies - the only difference is how a body gets reached: straight through for a script, by matching the first four letters the player types against a topic keyword for a conversation, or by a numeric key room code passes to game_room_script_entry() for a room.

Examples

script intro {
    text "Welcome."
    portrait_show 3 left
    check_flag MET_WIZARD == 0 {
        text "A wizard appears!"
        set_flag MET_WIZARD 1
    } else {
        text "The wizard nods at you."
    }
    wait_key
    portrait_hide
}

conversation wizard {
    topic "wiza" {
        text "I am the wizard of this land."
    }
    topic "*" {
        text "The wizard doesn't answer that."
    }
}

room 00 {
    entry STORY_ROOM00_LOOK_TREE {
        text "The tree has a knot hole."
    }
    entry STORY_ROOM00_USE_TREE {
        text "You knock on the tree, but nothing happens."
    }
    entry 6 {
        room_transition 01 10 5
    }
    entry 7 {
        room_transition_here 01
    }
    entry 8 {
        text "You break the seal."
        set_bit QUEST_FLAGS 1
    }
    entry 9 {
        text "You repair the seal."
        clear_bit QUEST_FLAGS 1
    }
}

Syntax basics

  • Comments: // to end of line or /* a block, possibly multi-line */.
  • Statements are separated by whitespace/ newlines, not punctuation - a trailing ; is accepted but never required.
  • Strings are double-quoted; the only escapes are \n, \t, \", and \\.
  • Numbers are decimal (42) or hex (0x2A).
  • Symbol names (MET_WIZARD, STORY_ROOM00_LOOK_TREE, ...) resolve against #define NAME VALUE lines in src/story.h at build time - nothing here is validated live in the browser; an unknown symbol or other syntax error surfaces when you build the cartridge.

Statements

text "..."
Shows a line of text in the two-line status area. Long text word-wraps; once both lines are full the engine pauses for a keypress, scrolls, and continues.
portrait_show ID (left|right)
Shows portrait ID (see Portrait mode) sliding in from off-screen at the given side. Pauses rain automatically if it was active, and resumes it on portrait_hide.
portrait_hide
Hides the portrait immediately, no animation.
set_flag NAME VALUE
Sets story flag NAME (an index into game_state.flags, named via #define in src/story.h) to VALUE (0-255).
set_bit NAME BIT
Sets bit BIT (0-7) of flag NAME, leaving its other bits untouched - a no-op if BIT >= 8. Lets one flag byte pack several independent yes/no facts; pair with check_flag NAME & BIT to read one back (see "check_flag comparisons" below).
clear_bit NAME BIT
Clears bit BIT (0-7) of flag NAME, leaving its other bits untouched - a no-op if BIT >= 8.
check_flag NAME CMP VALUE { ... } else { ... }
Branches on the flag's current value; the else branch is optional. Both branches are full statement sequences and may nest further check_flags. See "check_flag comparisons" below for CMP.
wait_key
Pauses until the player presses (and releases) a fresh key.
room_transition ROOM X Y
Queues a transition to ROOM, landing the player at half-tile (character-cell) coordinates X,Y - 0-39 and 0-21, the finer 40x22 grid, not the coarser 20x11 tile grid. Applied on the next safe frame, once this script has finished running.
room_transition_here ROOM
Same as room_transition, but keeps the player's current position instead of a fixed X,Y - for a door or edge that leads into a room continuing at the same map position.
sound ID
Reserved for a future sound-effect table; currently a no-op.
give_object TYPE QUANTITY
Adds QUANTITY of object type TYPE (see Object mode) to the player's inventory. QUANTITY 0 is legal but a no-op.

check_flag comparisons

== / !=
Equal / not equal to VALUE.
< / >
Less than / greater than VALUE.
<= / >=
Less than or equal / greater than or equal to VALUE.
&
Bit test: VALUE is a bit index 0-7, true when that bit of the flag byte is set - lets one flag byte pack several independent yes/no facts. There is no separate "bit clear" comparison; use the else branch instead.

Conversations

A topic's "keyword" is matched against the first four letters the player types, uppercased. A keyword of "*" is the fallback topic, tried when nothing else matches.

Rooms

An entry's KEY is whatever numbering convention the room's own code (rooms/XX.c) picks - e.g. a tile index for a tile-entry hook, or a reserved constant range for Look/Use hotspots - looked up via game_room_script_entry(KEY), which returns 1 if a matching entry ran or 0 otherwise (a normal, cheap outcome for a key nothing was authored for, not an error). There is no fallback/wildcard entry for rooms. Name keys via #define in src/story.h for readability, the same as flag names.

Resource IDs

The Resource ID field above selects which assets/scripts/<ID>.script file is open. 0x00-0xEF are room IDs - a room's script always uses the same ID as the room itself. 0xF0-0xFF are reserved for standalone scripts and conversations not tied to any one room, played via game_script_play().

This covers the DSL an author writes. The compiled binary format (opcodes, string table, topic/entry tables) is documented in tools/compile_script.py's module docstring, for anyone touching the compiler or the interpreter (modules/script.c) itself.
